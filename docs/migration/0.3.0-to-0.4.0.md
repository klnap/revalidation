# Migrate from `0.3.0`

Version 0.4.0 is a breaking protocol and configuration change. Do not run old and new producers against
the same endpoint during a rolling migration: the consumer accepts CloudEvents and Standard
Webhooks, not the `0.3.0` bearer-token envelope.

## HTTP destination

Replace the unnamed `target` or target array with a named `targets` record. Use a Standard Webhooks
secret (`whsec_` plus Base64-encoded key material) instead of a bearer token:

```ts
http({
  targets: {
    website: {
      url: process.env.REVALIDATION_URL!,
      secret: process.env.REVALIDATION_SECRET!,
    },
  },
})
```

By default, every event goes to every configured destination. Add a destination filter only when
that endpoint should receive a subset. Manual target selection narrows the configured targets and
does not bypass filters.

## Event envelope

Replace the package-specific `{ source, data }` envelope with CloudEvents 1.0. A single event uses
`application/cloudevents+json`; a batch uses `application/cloudevents-batch+json`. The old `source:
"payload"` value becomes an absolute CloudEvents source URI, and the old item data becomes the
typed CloudEvent `data`.

Update custom producers to emit `id`, `source`, `specversion`, and `type`. Keep one stable CloudEvent
ID when retrying the same event. Add an application schema that implements Standard Schema V1 for
each custom event source.

## Cache declarations and rules

Remove `defineRevalidationTags()` and the `@klnap/revalidation/consumers/next/tags` import. Move
the existing `tags` and `paths` declarations into the single `defineRevalidation()` call. Keep
`tags` and `paths` separate; do not convert them to delivery destinations.

Replace key-based event resolution with rules over CloudEvent source, type, operation, root resource,
and affected resources. Use object mappings for exact affected resource type/name matches. Use
`on()` selectors for source, operation, root-resource, or other compound conditions. All matching
rules execute; duplicate tag/path operations are removed.

The default cache mode remains immediate expiry. `stale` maps to Next.js's `"max"` profile. Literal
paths omit a type; dynamic route patterns default to `page`. Use `layout` where required.

## Custom dispatchers and consumers

Update custom dispatchers to accept CloudEvents and optional explicit named target selection.
Return one result per target chunk and support the `partial` aggregate status. A dispatcher must not
select destinations based on consumer invalidation rules.

Custom consumers must verify transport authentication before parsing, validate CloudEvents
envelopes, validate `data` with Standard Schema V1, and use the parsed output. Make cache effects
idempotent because retries can redeliver a request.

## Payload transaction behavior

Payload hooks still run before commit. The built-in plugin remains best-effort and fail-open; a
scheduled delay does not guarantee commit ordering. Preserve the orderable integration where the
host invokes its `onCommitted` or `onRolledBack` callback. Use an application-managed transactional
outbox when committed, durable delivery is required.
