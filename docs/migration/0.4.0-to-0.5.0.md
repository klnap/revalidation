# Migrate from `0.4.0`

The 0.5.0 candidate separates CloudEvents source identity from event-data validation. Update
producer and consumer configuration together.

## Payload producer

Set a stable absolute URI on every Payload plugin:

```ts
revalidation({
  source: 'https://cms.example/payload',
  dispatcher,
})
```

The former implicit `urn:klnap:revalidation:payload` source and `payloadSource` export are removed.
Keep the configured URI stable across retries and deployments that share one producer identity.

## Next.js consumer

Replace `mode: 'expire' | 'stale'` with native profiles. Use `profile: 'max'` for stale-while-
revalidate behavior, or `[tag, 'max']` to override one tag. The default remains immediate expiry
through `{ expire: 0 }`. Replace tag/path `{ value, mode/type }` descriptors with tuples:
`[tag, profile]` and `[path, 'page' | 'layout']`.

The built-in resource-change schema is registered automatically. Remove its `sources` entry and
select it by its event type:

```ts
defineRevalidation({
  secret: process.env.REVALIDATION_SECRET!,
  tags: { pages: '[locale]:pages' },
  rules: ({ tags }) => ({
    'payload.collection.pages': [tags.pages],
  }),
})
```

Custom schemas move from source-keyed `sources` to event-type-keyed `schemas`:

```ts
defineRevalidation({
  secret: process.env.REVALIDATION_SECRET!,
  schemas: { 'com.example.pricing.changed.v1': pricingSchema },
  allowedSources: ['https://billing.example/events'],
  rules: ({ on }) => [
    on({ type: 'com.example.pricing.changed.v1' }, ({ data }) => resolvePricing(data)),
  ],
})
```

The built-in schema cannot be replaced. `allowedSources` is optional and matches source URIs exactly.
Use source selectors when rule behavior depends on producer identity; they no longer select schemas.

## Event processing

The consumer validates every event in a request before running any rule or side effect. Duplicate
`(source, id)` identities in one request execute once. Equal IDs from different sources execute
independently.
